# SPEC-04 — Tiered Memory

**Phase 3** · Satisfies: §7.1 "Tiered memory" row · AC-05.

---

## 1. Purpose & graded requirement

`src/memory/` + `tests/test_memory_persistence.py` + `logs/memory_test.log`: **short-term + long/semantic
memory**, with a **cross-session recall test and a committed output log**. AC-05: the copilot uses facts
stated earlier in the interaction **and recalls prior-session context on a return visit**.

## 2. Contract

### 2.1 Tier 1 — short-term · `src/memory/short_term.py`

LangGraph `SqliteSaver` checkpointer over `config.CHECKPOINT_DB` (default `var/checkpoints.sqlite`).
Keyed by `thread_id`. Gives in-conversation context and resumability.

```python
def build_checkpointer() -> SqliteSaver           # sync context-managed, committed path
def thread_config(thread_id: str) -> dict          # {"configurable": {"thread_id": thread_id}}
```

### 2.2 Tier 2 — long-term / semantic · `src/memory/long_term.py`

**LangMem** store persisted to `config.MEMORY_DB` (default `var/memory.sqlite`), namespaced per claimant.

```python
NAMESPACE = ("claimant", "{claimant_id}")          # claimant_id is MASKED before use as a key

class MemoryRecord(BaseModel):
    kind: Literal["fact","preference","prior_claim","contact_pref","open_issue"]
    text: str                                       # masked, PII-free
    claim_id: str | None
    created_at: str
    source_run_id: str

async def remember(claimant_id, record: MemoryRecord) -> str      # returns memory id
async def recall(claimant_id, query: str, k: int = 5) -> list[MemoryRecord]
async def forget(claimant_id, memory_id) -> None                  # DPDP erasure hook (cited by P5)
```

Semantic recall uses the **same local Sentence-Transformers** embedder as the RAG tool (one model load,
one cost story).

### 2.3 What gets written to long-term memory

Written by `write_context` at these points, never by raw LLM discretion:

| When | Record |
|---|---|
| after `ingest` | `prior_claim` — "claim {masked id}, {loss_type}, reported {date}" |
| after `coverage` | `fact` — "policy {masked} product {product}, deductible {amount}" |
| after `router` | `open_issue` — "claim {masked id} routed {queue}, escalation {bool}" |
| on claimant preference stated in trusted turn | `contact_pref` |

**Never written:** unmasked identifiers, raw claimant narrative, anything derived from a quarantined string
without going through masking.

### 2.4 Recall into the graph

`ingest` calls `recall(claimant_id, query=<loss summary>, k=5)` and writes the result to
`state.memory_recall`. `select_context` injects it under a clearly labelled **trusted** section — memory is
first-party, so it is not fenced, which is exactly why nothing untrusted may be written into it.

## 3. Behaviour — the cross-session proof

`tests/test_memory_persistence.py` must prove **process-independent** persistence, not just a second call
on a live object:

1. **Session A** — build the app, run a claim for `CLT-882134` on `thread_id="t-A"`; a fact is written.
2. **Teardown** — close the checkpointer and the store, drop every in-memory reference.
3. **Session B** — build a *fresh* app and store from the same on-disk files, `thread_id="t-B"`
   (a genuinely new conversation), and ask a question whose answer requires the Session-A fact.
4. **Assert** — the fact is recalled, and the answer is not derivable from Session B's input alone.
5. **Also assert** — short-term tier: resuming `thread_id="t-A"` restores the checkpointed message history.

The test writes its own transcript to `logs/memory_test.log` via a logging handler **inside the test**
(Rule R1 — the log must be machine-generated by committed code). The log records, per step: session, thread
id, what was written, what was recalled, and the assertion result.

## 4. Evidence produced

| Artifact | Producer |
|---|---|
| `src/memory/{short_term,long_term}.py` | hand-written |
| `tests/test_memory_persistence.py` | hand-written |
| `logs/memory_test.log` | emitted **by the test run** |

## 5. Done when

- [ ] `pytest tests/test_memory_persistence.py -q` passes and regenerates `logs/memory_test.log`.
- [ ] The log shows a write in session A and a recall in session B with a **fresh** app instance.
- [ ] Resuming thread `t-A` restores prior messages (short-term tier).
- [ ] No unmasked identifier appears anywhere in `logs/memory_test.log` or in the memory store.
- [ ] `forget()` removes a record and is referenced by `docs/compliance.md` (P5) as the DPDP erasure control.
